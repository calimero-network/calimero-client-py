The public surface lives in the `calimero_client_py` module and is re-exported
from the `calimero` package: `Client`, `CloudClient`, `SoftPasskey`,
`CloudError` (with its subclasses `LoginRequired` and `WrongNode`) and `VERSION`. Every method is **synchronous** and returns plain Python values
decoded from the node's JSON (keys are the node's `camelCase`). A failing request
raises [`CloudError`](/reference/errors/); a malformed argument caught before
sending raises `ValueError`.

## `Client`

```python
Client(base_url, allow_mock=False, app_hash=None, tee_profiles=None,
       min_release=None, allow_debug_profiles=False, nodes=None)
```

`Client` is the preferred name. `CloudClient` is the same class under the name
earlier releases used (`Client is CloudClient`), kept so existing imports work.

A connection to one node of a cluster. The node is trusted only once its
attestation verifies (see [concepts](/get-started/concepts/)); nothing is sent
until the first request.

| Argument | Meaning |
| --- | --- |
| `allow_mock` | Accept development (mock) quotes. |
| `app_hash` | Hex of 32 bytes: the bundle the quote must bind. |
| `tee_profiles` | Accept real TDX quotes from images a signed mero-tee release lists under one of these profiles. Without it only mock quotes can be accepted. |
| `min_release` | The oldest mero-tee release accepted. |
| `allow_debug_profiles` | Accept a release's debug profiles (whose memory the host can read). |
| `nodes` | Other nodes of the same cluster, in the order to move to them when a node answers `421 WRONG_NODE` or is unavailable (see [recovery](#recovery)). Each is attested under the same policy. `node_url` names the node in use. |

### `Client.connect`

```python
Client.connect(cluster, *, tee_profiles=None, min_release=None, allow_mock=False,
               app_hash=None, allow_debug_profiles=False, directory=None, zone=None)
```

A client for the cluster named `cluster`, from the nodes the Calimero Cloud
node directory lists for it: `GET {directory}/{cluster}`, `directory`
defaulting to `https://manager.cloud.calimero.network/api/v2/directory`. The
policy arguments mean what they do for the constructor.

- Entries that are not an `http(s)` URL with a positive integer `weight` are
  dropped. An unknown cluster (`404`), a directory that cannot be reached, or a
  listing with no usable node raises `CloudError` with code `DIRECTORY` (its
  status is the directory's, 0 when it could not be reached).
- The nodes in `zone` come first, then the rest; within each group the order is
  weighted random. The first is the node in use, the others are its `nodes`.
- The directory is not trusted: every node is attested under this client's
  policy before anything is sent to it, so a bad listing can only make
  connecting fail.
- The listing is fetched again, best effort, once its `refreshAfterSeconds`
  have passed and after the client failed over: the node in use stays first,
  then the directory's order; nodes it no longer lists are dropped.

`node_urls` lists every node in the order the client moves through them.

### Recovery

A node that cannot be connected to is left for the next node by any request; a
read (`view`, `get`, `get_text`, `attestation`, `list_apps`, `get_app`,
`get_org`, `get_team`, `list_api_keys`) or a `call`
whose node answers `503` or times out is too. Core's client first sends a call
again to the same node for about nine seconds; the call then goes to the next
node with the same idempotency key (the client makes one when `call` is given
none), and the cluster answers it once, since the key is recorded in the app's
replicated log. Each node is tried once per request; after the last, the last
error is raised. `sign_in`, `sign_up` and refreshes are never sent again for
this. With one node nothing changes.

A request made with a session that the node answers `401 UNAUTHENTICATED` is
refreshed once and sent again: the node that signed the session may only have
been replaced or be out of reach, and any node takes the refresh. Requests
refused at the same time share that one refresh (a refresh token is used once).
`421 WRONG_NODE` moves the client to the next of `nodes` and sends the request
there once. Both refusals come before the node runs anything, so sending a call
again is safe. `sign_in` and `sign_up` answered `421` are not sent again (they
need the passkey again); a refresh answered `421` goes, with the same unspent
refresh token, to each next node in turn, once per node. See
[errors](/reference/errors/#restarts-and-other-nodes).

#### Upgrade keys: deploy from CI

An upgrade key (core 1.0.0-rc.10) upgrades one app to signed releases of its
package without a passkey, so a CI job can publish a release and move the app
to it. Whoever may upgrade the app makes it once, with their passkey; the key
is bound to the app, its package (by default the one the app runs) and that
package's signer as pinned when the key is made.

```python
# Once, signed in with a passkey:
key_id, key = owner.create_api_key(
    {"label": "ci", "upgrades": {"app": app_id}, "ttlSecs": 90 * 24 * 3600},
    passkey,
)
# In CI, with the key alone (store it as a secret):
ci = Client.connect("my-cluster")
ci.use_api_key(key)
ci.upgrade_app(app_id, version="1.4.0")
```

The node signs each such upgrade with the Ed25519 key the API key stands for
(`SHA-256("calimero.api-key.v1\0" || key)` as the seed) in place of a passkey
assertion, and logs that proof. Everything else the key is used for is refused
`403 UPGRADE_KEY_ONLY` (reads too); a `bundle`, another package or another app
is refused `403`; `revoke_api_key` stops it at once.

### Account recovery

Someone who loses every passkey gets back in with a recovery code made while
signed in (needs a node with core #4844). The code and a new passkey start a
recovery that waits 72 hours; during that time any passkey the account still
has cancels it; after, the new passkey finishes it, which ends every session
the account had and signs in. `me()` shows `recoveryCode` (whether one is set,
never the code) and `recoveryPending`.

| Method | Returns |
| --- | --- |
| `create_recovery_code(passkey)` | The code (`XXXX-XXXX-...`, 32 Crockford base32 characters), shown once; approved with a passkey the account has. A new code replaces the old. |
| `remove_recovery_code(passkey)` | `None`; approved with a passkey the account has. |
| `start_account_recovery(code, passkey)` | Signed out, with a new `passkey`: `{accountId, credentialId, startedAt, readyAt}`. The code is spent. A wrong or spent code raises `LoginRequired`, a recovery under way `RECOVERY_PENDING` (409), and a code that cannot be one `ValueError` before anything is sent. |
| `cancel_account_recovery(passkey)` | `None`; signed in, approved with a passkey the account already has. |
| `finish_account_recovery(passkey, account_id=None)` | Signed out, with the passkey the start registered, once `readyAt` has passed (`RECOVERY_NOT_READY`, 409, before): the session, which the client then uses. |
| `CloudClient.normalize_recovery_code(code)` | The code's canonical form (dashes and spaces dropped, upper case, `O` as `0`, `I`/`L` as `1`); `ValueError` for anything that cannot be a code. |
| `CloudClient.recovery_code_key(code)` | The Ed25519 public key (hex) the code stands for, the only thing the node records: `SHA-256("calimero.account-recovery-code.v1\0" \|\| canonical code)` is its seed. |

The code goes to the node over the sealed channel; the node signs the start
with the code's key, over the account and the new passkey, so the signature
cannot add any other passkey.

### Ops API

The operator's calls, with the node's ops token: `client.use_api_key(ops_token)`
first. The Ops API has no read path into apps' data. Its decisions (registering
and removing nodes, quotas, replica moves, and releases, outbound approvals and
upgrades where governance gives them to the operator) answer `428
OPERATOR_SIGNATURE_REQUIRED` until signed with the operator's Ed25519 key:
`client.use_operator_key(seed_hex)` (the 32-byte seed; the nodes run with
`--operator-key Client.operator_public_key(seed_hex)`) and the client signs
the bytes the node names and sends the decision again.

| Method | Returns |
| --- | --- |
| `ops_status()` | `{"node", "system", "governance", "groups", "nodes", "apps", "accounts"}`. |
| `ops_metrics()` | Prometheus metrics (`str`). |
| `ops_register_node(node_id, addr, zone="")` | `None`; a node started without `--bootstrap` then joins as a learner. |
| `ops_remove_node(node_id)` | The system group's status; refused while an app keeps a replica there. Runs on the system leader. |
| `ops_set_replicas(app, replicas)` | The app group's status after moving it to these node ids (at least 3). Runs on the app group's leader. |
| `ops_backup()` | How many encrypted snapshots this node wrote (the apps it leads, to `--backup-dir`). |
| `ops_quotas()`, `ops_set_quotas(quotas)` | The per-account limits; `ops_set_quotas` changes those it names (an unknown name is `UNKNOWN_QUOTA`). |
| `ops_approve_release(version, withdraw=False)` | Approves (or withdraws) a mero-tee release for every app, where the operator holds release approvals. |
| `ops_approve_outbound(package, prefixes=None, replace=False)` | Approves outbound URL prefixes for every app, where the operator holds outbound approvals. |
| `ops_upgrade_app(app, bundle=None, version=None, package=None, service=None, migrate=None)` | Upgrades an app, where the operator holds app upgrades. |
| `ops_upgrade_org(org, package, version, team=None, cascade=False, migrate=None)` | Starts an org-wide upgrade run, where the operator holds app upgrades. |
| `ops_served_origins()` | `{"fresh", "origins": [{"origin", "host", "label", "addedAt"}]}`: every served origin (custom domain) the cluster's log holds, by package label. |
| `ops_packages()` | The packages the operator installed. |
| `ops_upload_package(mpk)`, `ops_install_package(package, version)`, `ops_uninstall_package(package, version=None)` | Installs and uninstalls packages for the operator's upgrades. |

`ops_remove_node` and `ops_set_replicas` follow a `421 NOT_LEADER` answer to the
leader the node names (attested under the same policy, sent the same API key),
so they can be sent to any node.

## `SoftPasskey`

```python
SoftPasskey(rp_id="localhost", origin="http://localhost:3000")
```

An in-memory ES256 passkey for scripts and tests against development clusters.
`credential_id` is its credential id. Real users sign in from a browser;
services use API keys.

## `VERSION`

The package version, as a string.
