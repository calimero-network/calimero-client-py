- **`CloudError`** — a request failed. Its `args` are
  `(message, status, code, details)`:
  - `status` is the node's HTTP status, or `0` when the node could not be
    reached or attested (`code` is then `"TRANSPORT"`);
  - `code` is the node's error code, for example `CONFIRM_REQUIRED`;
  - `details` is a JSON string (`"null"` when there are none).
- **`LoginRequired`** (a `CloudError`, `401 UNAUTHENTICATED`) — the client's own
  refresh did not help, or there was no refresh token (an API key): sign in
  again.
- **`WrongNode`** (a `CloudError`, `421 WRONG_NODE`) — the node runs a mero-tee
  release the account's owners have not approved, and the client knows no other
  node that took the request: connect to another node of the cluster.
- **`ValueError`** — a malformed argument caught before sending (an `app_hash`
  that is not 32 bytes of hex, an unparseable URL, `parent` and `to_top` given
  together) or an answer missing a field the method returns.

```python
import json
from calimero_client_py import CloudError

try:
    client.call(app, "clear")
except CloudError as e:
    message, status, code, details = e.args
    if status == 0:
        print("node unreachable or not attested:", message)
    else:
        print(status, code, json.loads(details))
```

## Restarts and other nodes

A session token is signed by the node that issued it. Other nodes take it only
while they can vouch for that node's signing key, so when the issuer is
replaced, removed or out of reach (a rolling deploy, an image rollout), they
answer `401` — not because the user signed out. The client answers that itself:

- **`401 UNAUTHENTICATED`** to a request made with a session: it refreshes once
  (`POST /auth/refresh`, which any node takes) and sends the request again.
  Requests refused at the same time share that one refresh: a refresh token is
  used once, and a second use revokes the session. Only when the refresh is
  refused, or the request is refused again, is `LoginRequired` raised. A request
  made with an API key is not refreshed.
- **`421 WRONG_NODE`**: the client moves to the next of the `nodes` it was given
  (`Client(base_url, nodes=[...])`) and sends the request there once; `node_url`
  names the node in use. With no other node, or when the next one refuses too,
  `WrongNode` is raised with the node's `details`.

Sending a request again is safe, a call too: the node answers `401` and `421`
while it judges the credential, before it runs anything. Two are never sent
again, because a node refuses them only after spending something single-use:

- `sign_in` and `sign_up` answered `421` spent the passkey challenge. The client
  moves to the next node and raises `WrongNode`; sign in again.
- `refresh` answered `421` spent the refresh token, so it is not sent to another
  node (which would revoke the session). It is raised as `LoginRequired` with
  `"refusedWith": "WRONG_NODE"` in `details`; the next sign-in goes to the next
  node.

```python
from calimero_client_py import Client, LoginRequired, WrongNode

client = Client(urls[0], nodes=urls[1:], tee_profiles=["..."])
try:
    client.call(app, "set", {"key": "a"})
except LoginRequired:
    client.sign_in(passkey)
except WrongNode as e:
    print("no node of the cluster here serves this account:", e.args[3])
```
